# UI System And Interaction Contract

[DESIGN.md](../DESIGN.md) owns visual intent; [theme.css](../src/app/theme.css) owns runtime tokens. This guide owns shared controls, observable behavior, accessibility, and layout. [Product rules](GENTLEPATH.md) and [integration boundaries](INTEGRATIONS.md) remain authoritative for permissions and lifecycle.

Import from `@/components/ui`; inspect `/dev-settings/components` before adding an equivalent control. Feature services own retrieval, persistence, authorization, and invalidation. Generic UI receives data and callbacks. All labels, errors, previews, and accessible names come from [the strings catalog](STRINGS.md).

## Compose A Screen

Use Page → one PageHeader → work surfaces. PageHeader keeps a compact sage surface by default; owning intro wrappers can supply lilac or sunlight through `--page-header-tint`. Header icons are omitted; title, supporting copy, and actions remain together. Directories use DirectoryFilters, DataPanel/DataTable where appropriate, and DirectoryPagination. Supply stable keys and visible record links. Use MobileRecordRow for compact summaries; a wide table without one owns a labeled focusable horizontal scroller. Do not put long forms in table-sized frames.

Settings/forms use SplitSection, SectionStack, Field, and FormActions. Light/Dark previews use the fixed target palette tokens, independent of the current active theme. HorizontalCarousel owns scroll-snapped card rails with a visible partial next card, touch/trackpad scrolling, and a keyboard-focusable track. It has no previous/next controls. The feature variant gives sponsor placements a larger card with the same peek; configured rotation retains pause/resume, pauses during manual interaction or focus/hover, and respects reduced motion. Other canonical owners include Button/IconButton, UiIcon/IconTile, badges/chips, QueryBoundary/EmptyState, Modal/AlertModal/SheetPanel, Markdown/media controls, Stepper, and persistent segmented panels. Optional reviewed assistance stays callback-driven; no generation, microphone request, or save occurs automatically.

The public header reuses ThemeToggle through a focused public preference/presentation boundary, without mounting authenticated app providers. IconMenu supports an optional visible trigger label and native destination links as well as action callbacks; destination links preserve browser navigation semantics. Resource cards reserve at least two title lines, then show the description with ratings aligned below it above the footer. Collection readers reuse ResourceCard and the same responsive resource grid, including artwork, ratings, save actions, and full-card navigation. GoalStatusBadge maps Active to the shared info/blue intent, Completed to success/green, and Archived to neutral/gray in both list and detail views. Landing support topic groups align at the bottom of their shared subgrid row while keeping their natural content height; chips never stretch to fill an adjacent two-line group. Landing FAQs place a centered heading above a two-column grid of shared Accordion items, collapsing to one column at the public narrow-layout breakpoint. Each item keeps its natural height when a neighboring answer opens; DOM reading order, multiple-open behavior, focus, and reduced-motion behavior remain shared. The public landing header and Shared Moments hero fill the initial viewport, with normal document scrolling for every following section. The full-bleed illustration is a maintained asset; all headline copy and controls remain semantic HTML. Its fixed inverse text and sunlight action use `--landing-hero-*` tokens in both themes. The hero and its header have no animations, hover/press movement, or smooth anchor scrolling. Public section anchors override the workspace scroll margin so preceding sections do not remain above the target. LandingAnchorSync clears stale section fragments after manual scrolling leaves the selected section, using native history replacement while preserving incoming deep links and Back/Forward state. Informational support cards lift on fine-pointer hover, and toolkit entries add a quiet surface/illustration response; both device and saved reduced motion suppress movement. Public contact fields stay embedded below their introduction and use the domain-owned ContactForm with the same shared controls, validation, and draft retention. Confirmed contact success uses the shared toast service; validation and send errors stay inline.

The required onboarding route owns its centered branded setup layout and uses the shared Stepper with completed/current/upcoming semantics. Completed steps can be revisited while later steps stay unavailable until saved; state/error focus, unsaved drafts, API persistence, and child-profile modal behavior remain domain-owned. Child name/birthday groups use a one-pixel gap. A successful Finish Setup opens the illustrated community welcome with heading focus, saved confirmation, and a continue action that preserves the validated redirect. The onboarding variant of shared SuccessCelebration plays an eight-second sequence of rising trails, vibrant pastel fireworks, and a confetti finish after the successful transition. It never starts after a failed save or initial completed-account hydration; explicit Celebrate Again can replay it. Skip Celebration cancels it, and Continue remains available throughout. Device/saved reduced motion suppresses the scene; changing that preference or hiding the document stops an active scene. The welcome remains readable and stationary until the parent continues. Its artwork loads eagerly, and the scene waits for image decode or failure; confirmed completion and Celebrate Again never fade, scale, or stagger the welcome content. Setup artwork uses the shared statically imported, content-hashed illustration registry; the first step is preloaded and later active steps load eagerly so a newly selected step never depends on lazy-image intersection. The transparent children-step PNG is served directly from its hashed bundle URL to avoid a stalled negotiated WebP optimization request. Setup and welcome images fill positioned, explicitly sized frames with contain sizing and padding; their intrinsic size cannot extend the grid or overlap following text. Both use the theme-owned artwork canvas for a visible warm backdrop in light and dark. Shared Checkbox controls form outlined preference tiles in both setup and Family Preferences. State-benefit imagery uses contain sizing with padding, preserving the full illustration. Transparent illustration headers, banners, and resource cards also use contain sizing and keep complete silhouettes visible without landscape edge-fade overlays. Family birthdays stay readable inline metadata rather than another card.

MilestoneLinksField is the shared bounded multi-selection owner for post, poll, resource, collection, guide, and article editors. It keeps topic tags separate, preserves unavailable retained links, and offers explicit removal. MilestoneLinkList hides unavailable guidance and links to the public guidance view. The dedicated milestone detail page has a full-width image header with an accessible branded fallback, followed by readable title/actions and naturally stacked sections. Compact in-page links wrap across rows instead of overflowing nested segmented controls. Canonical content cards retain their existing layouts; related sections keep separate URL paging and query boundaries. Private observation editors remain shared modals, while milestone guidance itself is a page. The directory keeps optional child tokens, with a selected token toggling off; it has no separate Browse Guidance pill or introductory explanation. The detail page retains its private-context help and browse action. Child-only progress/history controls disappear until a child is selected. Empty states span the full related grid width and center their icon, copy, and actions consistently across all detail sections, including tips and private history.

Resource coverage uses the shared Select in discovery and catalog-backed editor fields. ResourceSourceStatus displays nationwide/state coverage, the source-check date, and an official link in the reader. The staff source-check button is separate from review metadata, stays disabled while a draft is unsaved, and preserves the draft on conflicts or failures. Community profiles and experience/Small Wins flows reuse the canonical shell, segmented tabs, feed cards, composer, context controls, and shared feedback; private-share entry points open an empty composer.

## Navigation And Async State

Query failures and route errors share ErrorState: a neutral paper surface, a small amber warning icon, clear title/supporting copy, and a compact forest Try Again action. The action wraps below the copy in narrow panels and keeps its natural width. Omit redundant Error badges and large pink fills for recoverable reads. Retain alert semantics and specific authentication/permission/not-found messages. A query retry keeps its panel and previous message mounted, exposes pending state, and prevents duplicate clicks; failure restores keyboard focus to the retry action unless the user has moved elsewhere. Initial loads keep the normal loading treatment. Community and poll directory changes keep previous results mounted while fetching. Their Posts/Polls navigation prepares the target query and ballots before committing the route, preserving history and unsaved-choice guards; busy surfaces use a progress cursor. Shared ContentTransition animates confirmed content changes without remounting forms, and respects both motion preferences.

Use shared NavigationLink with the navigation guard for guarded links. Clean forms retain synchronous Next Link history/prefetch and modifier-click semantics. Committed client filters/pages use the supported History API; server-prop filters use router pushes. Back/Forward restores the previous page and filters. Private journal search stays local.

Guard registration alone does not intercept every arbitrary link or browser-history action. Register dirty/busy refs through useUnsavedFormGuard, pass guarded navigation to relevant actions, and clear dirty state only after successful save/discard. A confirmed discard releases the dirty ref immediately so navigation can continue while the destination loads; Keep Editing retains both the draft and its guard. Never persist private drafts in browser storage.

Place visible field labels above text fields, dropdowns, and search inputs, including directory filters. Shared Field has one vertical layout.

Show initial loading, background refresh, empty/no-results, and recoverable errors distinctly. Cancel/ignore superseded searches; debounce composition-safe remote search, clear immediately, and restore input focus. Keep safe mounted forms during transient refresh failures. Do not retain inaccessible content after 401/403/404. Mutations prevent duplicate submissions and retain inputs on failure; success feedback follows server confirmation.

PublicImageField in `services/media/components` composes the shared Field/Input/FileInput/Button controls with the container-owned upload hook. Guide covers/steps and milestone editors share URL validation, image preview/failure fallback, replacement/removal, public-visibility copy, file limits, cancellation, and busy behavior. Pending uploads retain the current preview and disable saving/navigation; failures keep the draft and current image available for recovery.

## Controls, Icons, And Destruction

MultiSelect’s selection formatter receives the count and selected labels. Its optional maximum selection count disables only unselected choices at the limit, leaving selected choices removable and Clear available; Select All is unavailable if the full set exceeds that limit. A visible Field label supplies the accessible name without a duplicate aria-label. Directory filters may summarize the count; form fields such as journal feelings show comma-separated labels. Both use the same keyboard-operable popup and clear action.

Button loading preserves dimensions and accessible name. Badge/Chip content and UiIcon keep icons inline with text; do not add block wrappers that stack a leading icon over its label. Every icon-only action needs an accessible name.

Use `variant="destructive"` for delete, remove, archive, unpublish, discard, and disabling/reducing access. It renders red text/icons on a transparent surface without a border or selection stroke; keyboard focus remains visible. Browser notification disabling and the account-deletion entry action are explicit exceptions: their destructive color has a 15% alpha background, with a 20% hover fill. Bookmark toggles retain their ordinary tone: a close-set bookmark + Save becomes a filled bookmark + Saved, and a second click unsaves directly without removal confirmation or removal toast. BookmarkButton owns the confirmed unsaved-to-saved particle burst; initial loading, saved hydration, failure, and unsaving do not animate. The animation surface stays mounted outside the button's busy content. Submit saves use BookmarkButton without toggle semantics and may show Saved while their clean confirmed draft remains mounted. Vote submission uses Cast Vote through an ordinary Button, keeping the bookmark action separate. General Save Changes actions retain the primary variant; platform-impact warnings belong to the confirmation. Selected heart reactions retain filled red hearts and Like/Liked copy. Confirm consequential actions through PresentationProvider with danger tone, object/scope/consequence, and the safe action initially focused. Do not style ordinary filter clearing or cancellation as destructive.

Record cards open their details/editor through a native stretched link or button; sibling actions remain above the stretched target and independently keyboard reachable. The shared `ui-card-open` utility is available for ordinary Card surfaces. Card actions live in the top-right IconMenu, whose default trigger is a vertical ellipsis without a chevron. Items support disabled/selected state and the destructive variant. Keep edit/delete out of card bodies and footers, and expose deletion inside editable record flows where the domain permits deletion. The profile page combines personal details and Family Preferences through shared editorial SplitSection surfaces, followed by account controls. Its original preference/account URLs remain available, and each form preserves its own draft, validation, save state, and navigation guard. Account settings, preferences, and role administration keep their established lifecycle and ownership limits.

Resource rating removal has no destructive button. Selecting the currently selected star opens an app-owned confirmation with Keep Rating focused; confirming clears the rating. Arrow-key changes continue to select a new rating normally.

Select/MultiSelect keep the trigger's authored width. The popup uses the longest option's intrinsic width, at least the trigger width, capped inside the viewport; wrap only when the viewport requires it. Preserve selected/disabled/highlight/focus states, visible scrolling, typeahead, and keyboard selection. Address/timezone/compact-segmented choices use this same owner.

Date of birth is date-only and serialized at UTC midnight; observations/schedules are instants displayed in the browser timezone with en-US formatting. Family profile birthdays, application Applied On, and the optional initial follow-up date use the shared React Aria DatePicker: typed date segments plus an app-owned, accent-colored calendar with en-US labels, keyboard navigation, and nested Escape/focus restoration. Birthdays additionally disable future dates; Applied On retains its optional date-only value and clear action. Other date/time fields retain their accepted native popup geometry/language. Use noValidate and schema messages, label/error associations, masked passwords with proper autocomplete, and first-invalid-field focus. TextArea defaults to one initial row and auto-grows for typed or restored content and width changes; editor callers retain that default. Names remain single-line Input fields.

## Layers, Focus, And Motion

Help FAQs use the shared Accordion with the plum tone: hover and expanded titles are purple, with the same measured panel animation and reduced-motion behavior. Notification inbox records use compact linked titles, explicit read toggles, and unboxed destructive archive icons. Mark All As Read is always visible beside Notification Settings in the page header and applies to the whole inbox independently of active filters; Manage retains scoped bulk operations.

Use Modal for composed forms and PresentationProvider for queued confirmations, sheets, and toasts. Consecutive alerts start with the safe action focused and preserve the original workflow trigger for restoration. Honor Escape, focus trap/restoration, safe areas, and reachable actions in long content. Modal supports initialFocusRef and a footer slot outside its scrolling body. Readers without custom actions receive a shared Close Dialog footer. All modal form actions and reader close actions use this slot; submit buttons retain native association with their uniquely identified form. Header, footer, and safe-area padding stay visible while the body scrolls. Inline comment composers keep inline actions; their modal variant uses the same footer slot. React Aria popups portal inside the modal's focus scope; Escape closes the popup before its parent. Higher confirmation layers must not dismiss/reopen the underlying dialog. Dirty guards share one pending discard decision.

Segmented choices use native radio semantics; more than two choices become Select below 600px. Persistent SegmentedPanels keep inactive drafts mounted/hidden/inert. Stepper eligibility and current/completed state belong to the caller; orientation does not change state. Reordering preserves handle focus after moves, including Safari. ReorderableList supports separate card rows; guide steps use this variant inside a bare SplitSection to avoid nested panels.

Shared motion CSS/helpers read theme timing and device/saved reduced-motion preferences. React Aria DisclosurePanel owns measured open/close height and exit timing. Rating/reaction feedback uses their shared owners. SuccessCelebration adds a bounded confetti/particle burst after confirmed save, vote, and discussion submissions; it never animates initial hydration or failure. Its onboarding variant uses a separate theme-owned duration and semantic colors, protects text/control regions, scales its particle count for narrow screens, and cleans up drawing and listeners on completion, skip, navigation, reduced motion, or a hidden document. Do not introduce per-screen timing constants or animate when reduced motion is active.

## Extending Shared UI

Interactive components exported from the UI barrel retain `'use client'` and named props interfaces; server consumers import that barrel too. Internal client-only subparts need no redundant boundary. Keep react-aria and react-aria-components on compatible shared PortalProvider versions.

Extend the canonical owner before adding a local equivalent. Add component reference states where relevant and verify a sibling workflow. [Verification](VERIFICATION.md) covers checks, keyboard, popups, narrow layouts, themes, and recovery; static audits supplement browser evidence.
